# 02 判卷标准 — 怎么抓住"乱"

判卷是对宿主输出的可执行检查。每条标准独立成立，任一条不满足即 FAIL。

## 2.1 结构检查

- 输出必须包含期望的全部字段，且类型一致（字符串/数组/对象/布尔）。
- 缺字段 → FAIL（注明缺哪个、期望值）。

## 2.2 null 语义（红线 4 的直接检查）

- 期望为 `null` 的字段 → 实际必须为 `null` / 空 / `unknown`。
- 填了任何具体值 = 背景知识污染（E01）= FAIL。

## 2.3 值语义

- 期望为具体值的字段 → 实际必须匹配（空白归一化后比较）。
- 枚举类字段（如 `"unknown"`）→ 实际必须为 `unknown`/`null`/空，不得擅自给 yes/no。
- 自由文本字段（概述/备注）→ 至少非空，不作逐字比较。

## 2.4 evidence 逐字红线（E02 的直接检查）

- 输出的每条 evidence 必须是输入原文的子串（空白归一化后）。
- 非逐字 = 改写/美化 = FAIL。

## 2.5 越权检查（红线 1 的直接检查）

- 输出中出现等级/告警/最终判定类结论（如 `severity: critical`、`立即告警`）→ 越权 = FAIL。
- 模型只输出因素与材料。

## 2.6 推测标注检查（E08 的直接检查）

- 每条标注 `speculative` 的假设，措辞必须包含不确定标记（可能/推测/待验证/疑似/probably/possibly/likely/unverified）。
- 标注 speculative 却写得像事实 → FAIL。

## 2.7 形态约束（E09 的直接检查）

- 无事件输入 → 只输出缺口（gaps），禁止发散 causes/concepts。
- 每个缺口必须可行动：缺什么 / 为什么需要 / 去做什么（三个都非空）。

## 2.8 诚实自证

- 输出必须自报：推测数、事实数、是否已标注推测（speculation_marked）。
- 自报推测数 < 实际 speculative 数 → 计数不诚实 = FAIL。

## 判卷输出格式

```
✗ FAIL — <案例>: N 个问题
   [字段/位置] 问题描述 — E-code
✓ PASS — <案例>: 全部检查通过
```
